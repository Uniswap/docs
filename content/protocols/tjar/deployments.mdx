The Factory and the Fee Controller each sit at the same address on every chain. Both are deployed through the canonical CREATE2 deployer with byte-identical initcode, which is what fixes the address.

## Token Jars

Individual Token Jars are not listed here. They are deployed permissionlessly by anyone, the Factory keeps no registry, and an operator can rotate a jar's releaser at any time.

Discover them by event instead. `JarDeployed` on the Factory announces a new pair, and `ReleaserSet` on a jar is the only proof of which releaser is currently live. See [Search Token Jars](/docs/protocols/tjar/guides/search-token-jars) for the full discovery flow.

## Verifying an Address

Before wiring anything on a chain, confirm the Factory's code is actually there.

```bash
cast code 0xfAc70EEEE259F2140CBbB8e3157b75A52ce39fee --rpc-url $RPC
cast call 0xfAc70EEEE259F2140CBbB8e3157b75A52ce39fee "FEE_CONTROLLER()(address)" --rpc-url $RPC
```

The second call should return the Fee Controller address above. A Factory wired to anything else is not this deployment.

<Callout type="warn">
A chain not listed here has no TJAR deployment. Funds sent to a predicted jar address on such a chain are stranded until the Factory lands there, and there is no guarantee it ever will. Deploy the jar before pointing any fee source at its address.
</Callout>
